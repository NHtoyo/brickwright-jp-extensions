# SPIKE Prime 実機確認手順（Hub OS 1.6.62）

## 対象と安全範囲

対象は SPIKE Prime Hub、Hub OS 1.6.62、Windows 11、Chrome の Web Bluetooth 接続です。この手順では、接続時の `InfoRequest` (`0x00`) と `DeviceNotificationRequest` (`0x28`, 100 ms) およびその応答だけを使って受信診断を行います。センサー通知要求は通常の受信購読で、ハブ上のプログラムを実行する命令ではありません。

Python tunnel (`0x32`)、プログラム転送・実行、モーター駆動、LED・画面表示、音声、ファームウェア操作は対象外です。確認中にそれらを送るブロックを実行しないでください。診断 reporter は受信済みの値を読むだけで、BLE 要求を追加送信しません。

この確認はユーザーが実機を操作するときだけ行います。fake-device テストの成功は実機動作を証明しません。

## 開始前

1. 本体と拡張機能を開発モードで起動し、本体の拡張機能ギャラリーで `NHtoyo開発版 (localhost:8000)` を選びます。
2. `NHtoyo開発版` と表示された SPIKE Prime 拡張を読み込みます。別の同じ ID の実装が読み込み済みという案内が出たら、ブロックを試さずエディターを再読み込みし、開発版を選び直します。
3. SPIKE Prime の「通信診断（表示用）」 reporter を確認できる状態にします。接続後に reporter を再評価すると最新スナップショットを表示します。通信診断（JSON） reporter は機械可読な保存用です。
4. ハブに接続する前に、車体やモーターが安全に手で動かせる状態かを確認します。動作ブロック、Python、プログラム転送は実行しません。

## 確認順序

各段階で診断 reporter を再評価し、表示値と時刻を記録します。

1. **ハブの接続** — 拡張機能の接続操作で対象ハブを選びます。表示が `Bluetooth 接続: 接続中` になることを確認します。
2. **ファームウェア情報** — `Hub OS バージョン` が `1.6.62` と表示されることを確認します。未受信ならそのまま記録し、後続の角度変化を成功扱いしません。
3. **0x29 応答** — `センサー通知要求: 応答あり` を確認します。`拒否`、`タイムアウト`、`送信失敗`、`不正な応答` の場合はその状態と最終通信エラーを記録し、再接続を繰り返さず確認を止めます。
4. **IMU通知件数** — 数秒待って再評価し、件数が増え、最終IMU通知時刻が `未受信` から時刻表示に変わるか確認します。件数が0のままなら、角度の0を受信済みの正常値と解釈しません。
5. **Pitch / Roll** — ハブ本体をゆっくり傾け、Pitch と Roll が変化するか確認します。Yaw は静止中に変化しにくい場合があるため、単独で合否判定しません。値が変わらない場合は動作ブロックを追加せず記録します。
6. **モーター角度** — ハブが接続状態のまま、スロットル用モーターを手でゆっくり回します。モーターを電気的に駆動するブロックは使いません。検出ポートと位置が更新されるかを確認します。モーターが手で動かせない場合や負荷がある場合は無理に回さず、この確認を飛ばします。
7. **切断・再接続** — エディターの切断操作を行い、`未接続` を確認します。その後、ユーザー操作で一度だけ再接続し、ファームウェア、0x29、IMU件数と時刻が新しい接続セッションの値に戻るか確認します。
8. **診断情報の保存** — 最終状態の「通信診断（表示用）」と「通信診断（JSON）」をそれぞれ記録します。JSON reporter の値はプロジェクトの変数へ一時的に写して保存するか、画面を撮影してください。実行するのは reporter の読み取りだけにし、表示・モーター・Python のブロックを追加しないでください。Windows の日時、Chrome バージョン、接続元の表示名、各段階での状態も一緒に記録します。

## 予期しない停止・異常時

ハブが停止した、応答しなくなった、または想定外の動作をした場合は、その場で試験を止めます。追加の送信系テストや再試行をせず、エディターから切断できる場合だけ切断します。診断値・発生時刻・直前に行った手順を保存してください。この手順内ではハブの再起動、電源操作、ファームウェア変更を指示しません。回復が必要な場合は LEGO の案内に従い、別途判断してください。

## この手順で確認しないこと

Python API の実行可否、表示命令、モーター駆動、LED・音声出力、Hub OS 1.6.62 の全レコード形式、他ファームウェアとの互換性は未検証です。診断値の変化が確認できても、SPIKE Prime の全機能が動作した証明にはなりません。
